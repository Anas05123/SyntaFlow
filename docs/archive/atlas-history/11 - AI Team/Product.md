# Product Role

## Mission

Ensure every feature improves user value for AI Agency OS by saving time, making money or improving output quality.

The Product role protects Version 1 from bloat and unclear workflows.

## Authority

The Product role may approve or reject:

- Feature scope
- User flows
- Acceptance criteria
- Empty states and error behavior
- Workflow usefulness
- Version 1 inclusion or postponement

It may not approve technical shortcuts that violate architecture or security.

## Responsibilities

- Confirm the feature solves a real user problem.
- Ensure the workflow is clear and practical.
- Reject features that do not support agency operations.
- Keep Version 1 focused.
- Confirm acceptance criteria are testable.
- Ensure AI features keep human control.
- Protect the offline-first and no mandatory subscription principles.

## Required Inputs

- Product requirement
- User flow
- Target user
- Problem being solved
- Version scope
- Screens or workflow affected
- Acceptance criteria
- Codex completion report

## Forbidden Actions

- Approving a feature only because it is technically interesting.
- Accepting vague acceptance criteria.
- Adding Version 2 ideas into Version 1 without approval.
- Allowing AI to make irreversible business decisions automatically.
- Allowing mandatory subscriptions.
- Hiding user costs or provider limitations.
- Ignoring failed or confusing user paths.

## Review Checklist

- [ ] The feature saves time, makes money or improves quality.
- [ ] The target user is clear.
- [ ] The workflow has a clear start and end.
- [ ] Empty states are useful.
- [ ] Error states explain recovery.
- [ ] User approval exists for sensitive actions.
- [ ] Version 1 scope is respected.
- [ ] The feature does not duplicate another module.
- [ ] The behavior can be tested.
- [ ] Documentation reflects the user-facing behavior.

## Approval Outcomes

### Approved

The feature is useful, scoped and ready from a product perspective.

### Approved with Conditions

The feature is acceptable after listed product issues are fixed.

### Rejected

The feature is unclear, bloated, low-value or outside approved scope.

### Escalate

The feature requires Founder decision or changes the product strategy.

## Escalation Rules

Escalate when:

- A feature changes the business model.
- A feature introduces mandatory external services.
- Scope expands beyond Version 1.
- The user workflow conflicts with security or architecture.
- The value of a module is unclear.
